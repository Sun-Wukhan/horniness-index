# Submissions backend

Lets anyone post from the site's Contribute form without a GitHub
account. `POST /submit` files the submission as a GitHub issue (labels
`nomination`, `web`); the admin view at `/admin` approves (adds the
`approved` label → the nominations bot files it into `community.csv`)
or rejects (closes the issue). GitHub Issues are the database.

## One-time setup (maintainer)

1. **Fine-grained GitHub token** — <https://github.com/settings/personal-access-tokens>
   → *Generate new token*:
   - Resource owner: `Sun-Wukhan`
   - Repository access: *Only select repositories* → `horniness-index`
   - Repository permissions: **Issues: Read and write** (Metadata: Read is automatic)
   - Copy the token (you won't see it again).
2. **Render service** — <https://dashboard.render.com> → *New +* →
   *Blueprint* → connect `Sun-Wukhan/horniness-index`. The repo's
   `render.yaml` defines `horniness-index-api` (free tier; it sleeps
   when idle, so the first submission after a nap takes ~30 s). Set:
   - `GITHUB_TOKEN` — the token from step 1
   - `ADMIN_PASSWORD` — your choice; it guards `/admin`
   (`ADMIN_SECRET` is generated by Render automatically.)
3. **Confirm the URL** — expected `https://horniness-index-api.onrender.com`
   (that is what the site's `API_BASE` points at). If Render assigns a
   different name, update `API_BASE` in `horniness-index.py`.

## Abuse posture

Public endpoint, layered defences: honeypot field, 5 submissions/hour
per IP, the same name/reason validation as the nomination bot — and
nothing reaches the site without an Approve click in `/admin`. The
token can only touch issues in this one repo; revoke it any time.
